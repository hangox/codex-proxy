## Incident window

- Time zone: Asia/Shanghai (UTC+8)
- Last recorded successful opaque compact: 2026-08-13 01:16:57
- First sustained 404-backed denial: 2026-08-13 02:33:51
- Diagnosis and restart: 2026-08-13 14:37-14:44

## Log evidence

Primary files:

- `/Users/lin/codex-proxy/data/compact-outcomes.jsonl`
- `/Users/lin/codex-proxy/data/error-log.jsonl`

On 2026-08-13, the compact outcome log contained:

- `denied`: 440

The dominant chain was:

1. opaque state restored successfully;
2. recompact started;
3. upstream returned `404 Not Found` in roughly 0.3-2 seconds;
4. v1 retry logic treated 404 as non-retryable;
5. the proxy returned HTTP 409 with `recompact_failed_original_account` because cross-account retry was disabled.

The 409 and `recompact_failed_original_account` are wrapper symptoms. The upstream 404 is the causal failure.

## Root cause

`src/proxy/codex-api.ts` still implements remote compaction v1 by posting to:

`/codex/responses/compact`

The current upstream supports the v2 flow through normal `/codex/responses`, using a `compaction_trigger` input item and returning one encrypted `compaction` output item. The proxy has not implemented that flow for its opaque compact bridge.

The timing also shows this is an upstream capability/protocol transition rather than a local deployment regression: the same long-running process successfully compacted until 01:16, then both `gpt-5.6-sol` and `gpt-5.6-luna` began receiving fast 404s from the v1 endpoint at 02:33.

## Implemented fix

`src/proxy/codex-api.ts` now uses remote compaction v2 first:

1. send the compact input through the normal Responses transport;
2. append a `compaction_trigger` item;
3. use compaction request metadata/identity headers;
4. collect output items from the stream and usage from `response.completed`;
5. require exactly one `compaction` output item;
6. retain user messages client-side within the same approximate 64K-token budget used by current Codex, then append the encrypted compaction item;
7. convert the installed history and usage into the existing `CodexCompactResponse` contract;
8. fall back to legacy v1 only when the backend explicitly reports that v2/the trigger is unavailable; quota, authentication, context, malformed-output, transient, and cancellation failures do not send a second compact request.

The cancellation path was also corrected so an aborted WebSocket request does not start a second HTTP request.
